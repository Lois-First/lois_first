# 《C++ Primer》第 5 版详细总结：第 7-12 章

## 第 7 章 类

### 类是什么、解决什么问题

类把数据表示和操作数据的函数组合成一个类型，并用访问控制保护不变量。使用者依赖公有接口，不应依赖私有存储方式；这样实现可以变化而不破坏调用代码。

```cpp
class Account {
public:
    explicit Account(std::string owner, long cents = 0)
        : owner_(std::move(owner)), cents_(cents) {
        if (cents < 0) throw std::invalid_argument("negative balance");
    }
    const std::string &owner() const { return owner_; }
    long balance() const { return cents_; }
    void deposit(long cents) {
        if (cents <= 0) throw std::invalid_argument("invalid deposit");
        cents_ += cents;
    }
private:
    std::string owner_;
    long cents_ = 0; // C++11 类内初始值
};
```

`owner()` 返回 const 引用避免复制，同时不允许调用者修改内部名字。构造函数检查初值，`deposit` 检查后续操作，共同维持余额不为非法输入的约束。

### 构造函数与初始化列表

构造函数没有返回类型。成员在进入函数体之前就已初始化，所以应使用初始化列表，而不是先默认构造再赋值。引用、const 成员和没有默认构造函数的成员必须在列表中初始化。

成员实际按类内声明顺序初始化，与初始化列表顺序无关。列表最好也按声明顺序书写，避免一个成员使用尚未初始化的另一个成员。

`explicit` 禁止单实参构造函数参与隐式转换。多参数构造函数在 C++11 列表初始化下也可能成为转换构造函数，因此同样可以标 `explicit`。

### `this`、const 成员和重载

成员函数隐含 `this` 指针。普通成员中的类型近似 `Class* const`，const 成员近似 `const Class* const`。因此 const 对象只能调用 const 成员。

```cpp
char &at(std::size_t i) { return data_[i]; }
const char &at(std::size_t i) const { return data_[i]; }
```

这组重载让普通对象获得可修改引用，const 对象获得只读引用。

### 委托构造、默认与删除函数

```cpp
class Point {
public:
    Point() : Point(0, 0) {}             // 委托
    Point(int x, int y) : x_(x), y_(y) {}
    Point(double, double) = delete;      // 禁止易丢精度调用
private:
    int x_ = 0, y_ = 0;
};
```

`= default` 明确请求编译器生成默认实现；`= delete` 让不允许的操作在编译时报错。委托构造函数先完成目标构造函数，再执行自己的函数体。

### 友元、静态成员和聚合

友元不是类成员，但可访问私有部分，常用于对称运算符或紧密协作类型。友元声明只授予权限，通常还需在适当作用域提供普通声明。

静态成员属于类而非每个对象；静态成员函数没有 `this`。C++11 通常仍需在源文件定义非 inline 静态数据成员。

聚合是没有用户提供构造、私有/受保护非静态成员等限制的简单类型，可按成员顺序列表初始化。若类型需要维持不变量，应提供构造函数而非依赖聚合初始化。

## 第 8 章 IO 库

### 流类型和继承关系

`istream/ostream` 处理一般字符 IO；`ifstream/ofstream/fstream` 连接文件；`istringstream/ostringstream/stringstream` 连接内存字符串。文件流和字符串流继承相应基础流，因此接受 `istream&` 的函数也可处理文件或字符串。

```cpp
std::vector<int> parse_numbers(const std::string &line) {
    std::istringstream in(line);
    std::vector<int> values;
    for (int value; in >> value; ) values.push_back(value);
    return values;
}
```

### 状态机

| 状态 | 意义 | 恢复方式 |
|---|---|---|
| `goodbit` | 没有错误 | 无需恢复 |
| `eofbit` | 到达文件尾 | `clear()` 后才能继续其他操作 |
| `failbit` | 格式解析失败等可恢复错误 | `clear()` 并丢弃坏输入 |
| `badbit` | 设备或缓冲区严重错误 | 通常不能可靠恢复 |

`good()` 仅在完全无状态位时为真；`fail()` 检查 fail/bad；`eof()` 只说明 EOF 位。最可靠的读取循环仍是把读取操作本身放入条件。

### 缓冲与刷新

输出先进入缓冲区，缓冲满、流析构、程序正常结束或显式刷新时写出。`endl`、`flush`、`unitbuf` 会刷新；频繁刷新影响性能。输入流默认 tie 到 `cout`，读取前会刷新交互提示。

### 文件模式

| 模式 | 作用 |
|---|---|
| `in` / `out` | 输入 / 输出 |
| `app` | 每次写都定位到末尾 |
| `ate` | 打开后初始定位末尾，之后可移动 |
| `trunc` | 打开时截断原文件 |
| `binary` | 二进制模式，避免文本换行转换 |

```cpp
void append_log(const std::string &path, const std::string &message) {
    std::ofstream out(path, std::ios::app);
    if (!out) throw std::runtime_error("cannot open " + path);
    out << message << '\n';
    if (!out) throw std::runtime_error("write failed");
}
```

只检查打开成功还不够，写入过程中磁盘也可能失败。

### 格式化与随机访问

`setw` 只影响下一个字段；`setprecision` 在 defaultfloat 下表示有效位，在 `fixed` 下表示小数位。`boolalpha` 输出 `true/false`。`seekg/tellg` 控制输入位置，`seekp/tellp` 控制输出位置；文本模式位置不一定是简单字节偏移。

## 第 9 章 顺序容器

### 如何选择容器

| 容器 | 存储和复杂度 | 选择理由 |
|---|---|---|
| `vector` | 连续；随机访问 O(1)，尾插摊销 O(1) | 默认首选、缓存友好 |
| `deque` | 分段连续；随机访问 O(1)，两端操作 O(1) | 频繁头尾插入 |
| `list` | 双链表；已知位置插删 O(1) | 需要稳定迭代器或 splice |
| `forward_list` | 单链表；最小节点开销 | 只需单向遍历 |
| `array<T,N>` | 内嵌固定数组 | 固定大小且需要容器接口 |
| `string` | 连续字符 | 文本操作 |

链表的 O(1) 插入不包括找到位置的成本，且节点分配与缓存不命中可能比 vector 移动元素更慢。

### 通用容器操作

`begin/end/cbegin/cend` 获取边界；`size/empty` 查询；`front/back` 访问端点；`insert/emplace` 插入；`erase/clear` 删除；`swap` 交换内容。对空容器调用 `front/back` 是未定义行为。

构造可来自大小、值、迭代器范围或初始化列表：

```cpp
std::list<int> source{1, 2, 3};
std::vector<long> target(source.begin(), source.end());
```

迭代器范围构造允许元素类型转换，但要求 `[first,last)` 合法且可达。

### 插入、删除与 `emplace`

`push_back(x)` 先拥有一个 x，再复制/移动入容器；`emplace_back(args...)` 直接用参数构造元素。它不一定比 push 更快，不要把已有对象机械地改成 emplace。

`insert` 返回指向插入元素的迭代器；`erase` 返回删除区间之后的迭代器，因此正确删除循环为：

```cpp
for (auto it = values.begin(); it != values.end(); ) {
    if (*it < 0) it = values.erase(it);
    else ++it;
}
```

### `vector` 容量和失效

`size` 是已构造元素数，`capacity` 是无需重新分配可容纳的数量。`reserve` 只改变容量，`resize` 构造或销毁元素。重新分配使所有迭代器/指针/引用失效；删除会使删除点及之后的位置失效。

### `list` 和 `forward_list` 特有操作

`splice` 在链表间转移节点，不复制元素；`list::sort/merge/remove/unique/reverse` 是成员函数，因为普通算法通常要求随机访问或无法调整链表链接。

`forward_list` 只能通过“前一个位置”修改，使用 `before_begin`、`insert_after`、`erase_after`，且标准没有 `size()` 以维持极小开销。

### 字符串额外操作

`string` 支持位置加长度形式的 `insert/erase/replace`，以及 `find/rfind/find_first_of` 等搜索。位置是无符号 `size_type`，失败为 `npos`。`stoi/stol/stod` 把字符串转数值，可通过位置参数获知已解析字符数，并可能抛 `invalid_argument/out_of_range`。

## 第 10 章 泛型算法

### 算法与容器的分工

算法只通过迭代器读写元素，不知道容器类型，也通常不直接改变容器大小。它们的模板要求由迭代器类别和元素操作决定：`find` 只需输入迭代器，`sort` 需要随机访问迭代器。

### 只读算法

`find/count` 按值比较；`find_if/count_if` 使用谓词；`accumulate` 的第三参数既是初值又决定累计类型：

```cpp
double total = std::accumulate(v.begin(), v.end(), 0.0); // 保留小数
```

若写 `0`，每步可能按 int 累加并截断。

### 写算法与输出空间

算法不会自动扩大普通目标容器。`copy(src.begin(),src.end(),dest.begin())` 要求 dest 已有足够元素；需要追加时使用 `back_inserter(dest)`。

```cpp
std::vector<int> positives;
std::copy_if(v.begin(), v.end(), std::back_inserter(positives),
             [](int x) { return x > 0; });
```

插入迭代器包括 `back_inserter`、`front_inserter`、`inserter(container,pos)`。流迭代器 `istream_iterator`/`ostream_iterator` 把流适配为迭代器。

### 排序和去重

`sort` 不稳定，`stable_sort` 保留等价元素相对顺序。`unique` 只把相邻重复项移到逻辑尾，所以通常先排序，再 erase：

```cpp
std::sort(words.begin(), words.end());
auto new_end = std::unique(words.begin(), words.end());
words.erase(new_end, words.end());
```

### Lambda

Lambda 是匿名函数对象：`[捕获](参数) mutable/异常/返回类型 {函数体}`。值捕获在创建闭包时复制；引用捕获要求原对象在调用时仍存活。异步保存 Lambda 时尤其不能捕获短命局部引用。

```cpp
auto longer_than(std::size_t n) {
    return [n](const std::string &s) { return s.size() > n; };
}
```

### `bind` 与可调用适配

`std::bind(f, fixed, _1)` 重排或绑定参数，`std::ref(x)` 强制引用绑定。Lambda 通常更直观且类型错误更清楚。反向迭代器的 `base()` 指向当前元素之后的正向位置，进行 erase 时要仔细转换。

## 第 11 章 关联容器

### 有序和无序容器

`map/set` 通常用平衡树，按比较器有序，操作 O(log n)。`unordered_map/set` 用哈希桶，平均 O(1)，不保持顺序，最坏 O(n)。`multi` 版本允许等价键。

### `map` 的值类型与访问

`map<K,V>::value_type` 是 `pair<const K,V>`，键不可经迭代器修改，否则会破坏顺序。`operator[]` 在键不存在时插入值初始化的 V，适合计数，不适合纯查询。

```cpp
std::map<std::string, std::size_t> frequency;
for (const auto &word : words) ++frequency[word];

auto it = frequency.find("C++");
if (it != frequency.end()) std::cout << it->second;
```

`at(key)` 不插入，缺键抛 `out_of_range`。`insert/emplace` 对唯一键容器返回 `pair<iterator,bool>`，bool 说明是否插入。

### 范围查询与自定义比较

`lower_bound(k)` 是第一个不小于 k；`upper_bound(k)` 是第一个大于 k；`equal_range` 同时返回二者，适合 multimap。比较器必须建立严格弱序，不能用 `<=`。

### 无序容器

自定义键需要相等关系和哈希。`bucket_count` 查看桶数，`load_factor=size/bucket_count`，`max_load_factor` 控制再哈希阈值，`reserve(n)` 为预计元素数预留。

```cpp
struct PointHash {
    std::size_t operator()(const Point &p) const noexcept {
        return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);
    }
};
```

相等对象必须产生相同哈希；不同对象允许碰撞。

## 第 12 章 动态内存

### 为什么需要动态内存

动态对象的生命周期不由创建它的块作用域直接决定，适合大小运行时确定、跨作用域共享或多态对象。但裸 `new/delete` 容易泄漏、重复释放和异常不安全，现代代码应让资源立刻进入 RAII 对象。

### `shared_ptr`

共享所有权由控制块计数。拷贝增加强引用，析构/重置减少；强引用为零时删除对象。`use_count()` 主要用于诊断，不应驱动并发逻辑。

```cpp
std::shared_ptr<Record> load() {
    return std::make_shared<Record>(constructor_args);
}

auto p = load();
auto q = p;       // 共同拥有
p.reset();        // q 仍保持对象存活
```

优先 `make_shared`：对象和控制块通常一次分配，且构造表达式异常安全。不要从同一裸指针分别构造两个 shared_ptr，它们会建立两个控制块并重复删除。

### `unique_ptr`

表达唯一所有权，不可复制、可以移动。`release()` 只放弃指针而不删除，调用者必须接管；`reset(p)` 删除旧对象并接管新指针；`get()` 只观察，不能据此创建另一个所有者。

```cpp
std::unique_ptr<Widget> make_widget() {
    return std::unique_ptr<Widget>(new Widget); // C++11；C++14 用 make_unique
}

void consume(std::unique_ptr<Widget> p);
consume(make_widget()); // 明确转移所有权
```

### `weak_ptr`

`weak_ptr` 观察 shared_ptr 控制的对象但不增加强引用，用于缓存和打破环。`lock()` 原子地尝试获得 shared_ptr；对象已销毁则返回空。

```cpp
if (auto owner = weak.lock()) owner->use();
```

### 动态数组和 `allocator`

`new T[n]` 必须配 `delete[]`，无法自然携带长度，优先 `vector<T>`。`unique_ptr<T[]>` 能自动 `delete[]`，但仍不提供大小。

`allocator<T>` 把原始内存分配和对象构造分离：`allocate` 得到未构造内存，`allocator_traits::construct/destroy` 管理对象，`deallocate` 释放。它用于容器实现等底层场景，普通业务代码不应手工使用。

### 文本查询示例的设计意义

原书文本查询使用 `shared_ptr<vector<string>>` 共享整个文件，用 `map<string,shared_ptr<set<line_no>>>` 建立倒排索引。关键不在功能本身，而在所有权设计：查询结果可廉价复制，并保证其引用的文件和行号集合仍存活。
