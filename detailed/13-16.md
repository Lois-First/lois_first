# 《C++ Primer》第 5 版详细总结：第 13-16 章

## 第 13 章 拷贝控制

### 五个特殊成员函数

类通过析构函数、拷贝构造、拷贝赋值、移动构造、移动赋值控制对象复制、转移和销毁。编译器可隐式声明它们，但是否生成、是否删除以及逐成员操作是否正确，取决于成员类型和用户声明。

```cpp
class Buffer {
public:
    explicit Buffer(std::size_t n)
        : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer &rhs)
        : size_(rhs.size_), data_(new int[rhs.size_]) {
        std::copy(rhs.data_, rhs.data_ + size_, data_);
    }

    Buffer(Buffer &&rhs) noexcept
        : size_(std::exchange(rhs.size_, 0)),
          data_(std::exchange(rhs.data_, nullptr)) {}

    Buffer &operator=(Buffer rhs) {
        swap(*this, rhs); // rhs 是副本或移动所得临时对象
        return *this;
    }

    friend void swap(Buffer &a, Buffer &b) noexcept {
        using std::swap;
        swap(a.size_, b.size_);
        swap(a.data_, b.data_);
    }
private:
    std::size_t size_ = 0;
    int *data_ = nullptr;
};
```

上例展示深拷贝、资源转移和 copy-and-swap。赋值参数按值接收，先成功构造临时副本，再交换，提供强异常保证并自然处理自赋值。`std::exchange` 是 C++14；纯 C++11 可手工读取再清空源对象。

### 合成、删除和三/五/零法则

合成拷贝逐成员拷贝，内置指针只复制地址，若指针拥有资源就会重复释放。定义析构函数通常说明类直接管理资源，此时必须审查所有拷贝和移动操作，即三法则/五法则。

更好的零法则是让 `vector`、`string`、智能指针等 RAII 成员管理资源，类无需声明任何特殊成员：

```cpp
struct Document {
    std::string title;
    std::vector<std::string> lines;
};
```

若成员不可拷贝（如 `unique_ptr`），合成拷贝会被定义为删除。用户声明拷贝、移动或析构中的某些函数会抑制其他移动函数生成，实际设计应显式 `= default` 或 `= delete` 表达意图。

### 拷贝构造和拷贝初始化

`T x(y)` 通常直接初始化；`T x = y` 是拷贝初始化，也可能调用移动构造或被复制消除。函数非引用参数和按值返回也涉及拷贝初始化。`explicit` 构造函数不参与拷贝初始化。

### 移动语义

右值引用 `T&&` 能绑定到即将销毁的对象。`std::move(x)` 不移动任何数据，只把 x 转成可匹配移动重载的将亡值。移动后对象必须可析构、可赋值，但其具体值通常未指定。

移动构造应尽量 `noexcept`。`vector` 扩容需要强异常保证；若元素移动可能抛异常且可拷贝，vector 通常选择复制，避免移动一半后无法恢复。

### 引用限定成员

成员函数可用 `&`/`&&` 限定调用对象值类别：

```cpp
class Text {
public:
    Text &sort() & { std::sort(data.begin(), data.end()); return *this; }
    Text sort() && { std::sort(data.begin(), data.end()); return std::move(*this); }
private:
    std::string data;
};
```

它能防止对临时对象返回悬空引用，并为临时值提供高效接口。

## 第 14 章 重载运算与类型转换

### 设计原则

重载运算符是具有特殊名字的函数，至少一个操作数必须是类或枚举。不能改变优先级、结合律和操作数数量。应保持内置运算符的直觉：`+` 不修改操作数，`+=` 修改左侧，比较运算保持一致。

### 成员还是非成员

赋值、下标、调用和箭头必须是成员。需要左操作数隐式转换的对称运算通常写非成员，并在需要私有访问时设为友元。

```cpp
class Money {
public:
    explicit Money(long cents) : cents_(cents) {}
    Money &operator+=(const Money &rhs) { cents_ += rhs.cents_; return *this; }
    friend Money operator+(Money lhs, const Money &rhs) {
        lhs += rhs;
        return lhs;
    }
    friend bool operator==(const Money &a, const Money &b) {
        return a.cents_ == b.cents_;
    }
private:
    long cents_;
};
```

`operator+` 复用 `+=`，按值 lhs 允许编译器对左操作数移动。若定义 `<`，必须与 `==` 表达的等价关系和业务顺序一致。

### 输入输出运算符

输出运算符第一个参数为 `ostream&`，输入为 `istream&`，都返回流引用以支持链式调用。输入函数应检查格式，并在失败时把对象恢复到有效状态。

```cpp
std::istream &operator>>(std::istream &in, Date &date) {
    Date temp;
    char dash1, dash2;
    if (in >> temp.year >> dash1 >> temp.month >> dash2 >> temp.day &&
        dash1 == '-' && dash2 == '-' && temp.valid())
        date = temp;
    else
        in.setstate(std::ios::failbit);
    return in;
}
```

### 下标、递增和箭头

下标通常提供 const/非 const 两个版本。前置递增无哑参数，后置版本以 `int` 参数区分并返回旧值副本。自定义 `operator->` 必须返回指针或另一个具有 `operator->` 的对象，编译器会递归调用直到得到指针。

### 函数对象与标准库

重载 `operator()` 的对象可保存状态，比函数指针灵活。`std::function<R(Args...)>` 类型擦除函数、Lambda、bind 和函数对象；空 function 调用抛 `bad_function_call`。`std::bind` 绑定/重排参数，但 Lambda 通常更清晰。

### 类型转换

单参数构造函数把其他类型转成当前类；转换运算符 `operator T() const` 把当前类转成 T。二者过多会造成二义性。C++11 `explicit operator bool()` 只允许明确转换和条件上下文，适合流、智能句柄等“是否有效”判断。

```cpp
explicit operator bool() const noexcept { return handle_ != invalid; }
```

不要同时提供多个可互转算术类型的隐式转换，否则运算符解析容易产生歧义或意外精度损失。

## 第 15 章 面向对象程序设计

### 运行时多态

基类定义共同接口，派生类重写虚函数。通过基类引用/指针调用虚函数时，运行时根据对象动态类型分派；按值存为基类会发生切片，只剩基类子对象。

```cpp
class Quote {
public:
    Quote(std::string isbn, double price)
        : isbn_(std::move(isbn)), price_(price) {}
    virtual ~Quote() = default;
    virtual double net_price(std::size_t n) const { return n * price_; }
protected:
    double price_ = 0;
private:
    std::string isbn_;
};

class BulkQuote final : public Quote {
public:
    using Quote::Quote;
    double net_price(std::size_t n) const override {
        return n >= minimum_ ? n * price_ * (1 - discount_) : n * price_;
    }
private:
    std::size_t minimum_ = 10;
    double discount_ = 0.2;
};
```

多态基类析构必须 virtual，否则通过 `Base*` 删除派生对象是未定义行为。`override` 让编译器检查签名确实重写；`final` 禁止继续重写或继承。

### 访问控制与继承方式

派生类可访问 protected 成员，但只能通过派生对象访问；用户不能访问。公有继承保留“Derived 是 Base”的替换关系。私有/保护继承改变基类接口可见性，多用于实现复用，组合通常更清楚。

### 构造、析构与虚调用

构造顺序：基类、成员、派生类函数体；析构相反。基类构造期间派生部分尚不存在，所以虚调用只分派到当前正在构造的层次；析构同理。不要在构造/析构中依赖派生重写。

### 抽象基类和纯虚函数

`virtual f() = 0` 使类抽象，不能直接创建对象。纯虚函数仍可有定义，供派生类显式调用，但必须在类外定义。接口类通常只有纯虚函数和虚析构。

### 动态转换

`dynamic_cast<Derived*>(base)` 失败返回 nullptr；引用转换失败抛 `bad_cast`。它要求源类型多态。若经常需要 dynamic_cast 来决定行为，往往说明应增加虚函数。

### 容器中的多态对象

`vector<Quote>` 会切片，应保存 `shared_ptr<Quote>` 或 `unique_ptr<Quote>`：

```cpp
std::vector<std::shared_ptr<Quote>> basket;
basket.push_back(std::make_shared<BulkQuote>(/*...*/));
for (const auto &item : basket) total += item->net_price(20);
```

## 第 16 章 模板与泛型编程

### 模板是什么

模板是生成函数或类的规则。定义阶段检查不依赖模板参数的内容，实例化阶段替换具体参数并检查依赖内容。因此模板定义通常必须放在头文件，对使用点可见。

```cpp
template<class T, class Compare = std::less<T>>
const T &smaller(const T &a, const T &b, Compare comp = Compare{}) {
    return comp(b, a) ? b : a;
}
```

模板参数可以是类型、非类型常量和模板。非类型参数必须满足标准允许的编译期实体类别；C++11 常见为整数、枚举、指针/引用。

### 类型推导和引用折叠

按值参数会忽略实参引用和顶层 const，数组/函数退化为指针。`const T&` 保留底层 const。形如 `T&&` 且 T 参与推导时是转发引用：左值推导 T 为 `U&`，经引用折叠 `U& &&` 成为 `U&`；右值推导为 U，参数为 `U&&`。

### `std::move` 与 `std::forward`

`move` 无条件转成右值；`forward<T>` 仅在 T 记录原实参值类别时有条件恢复。完美转发包装器：

```cpp
template<class F, class... Args>
auto call(F &&f, Args&&... args)
    -> decltype(std::forward<F>(f)(std::forward<Args>(args)...)) {
    return std::forward<F>(f)(std::forward<Args>(args)...);
}
```

函数体内具名的 `arg` 永远是左值，所以必须 forward，不能直接传递。

### 可变参数模板

`class... Args` 声明类型参数包，`sizeof...(Args)` 得到数量，`pattern...` 展开。C++11 常用递归终止：

```cpp
void print(std::ostream &) {}

template<class T, class... Rest>
void print(std::ostream &os, const T &first, const Rest&... rest) {
    os << first;
    if (sizeof...(rest)) os << ", ";
    print(os, rest...);
}
```

### 依赖名与 `typename`

编译器无法知道 `T::value_type` 是类型还是静态值，依赖类型前要写 `typename T::value_type`。基类依赖模板参数时，其成员查找也会延迟，常需 `this->member` 或显式限定。

### 显式实例化与特化

显式实例化定义 `template class vector<string>;` 强制生成实例；`extern template` 抑制其他翻译单元重复实例化。显式特化为某组参数提供不同定义，它不是重载；函数模板通常优先通过普通重载表达特殊行为。

类模板可以偏特化，如 `remove_reference<T&>`；函数模板不能偏特化。

### 类型特征与 SFINAE

`<type_traits>` 在编译期描述/转换类型：`is_integral`、`is_same`、`remove_reference`、`decay`、`enable_if`。替换模板参数时若立即上下文无效，候选被丢弃而非硬错误，这就是 SFINAE。

```cpp
template<class T>
typename std::enable_if<std::is_integral<T>::value, T>::type
twice(T value) { return value * 2; }
```

C++20 concepts 能更直接地表达同类约束，但理解 SFINAE 对阅读 C++11/14/17 库仍很重要。
